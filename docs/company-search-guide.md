# 기업 검색과 재무 데이터 수집

기업 검색 → 선택 기업의 공시·재무 수치 조회 → 질문 처리의 데이터 경로를 설명한다. 기업 목록 등재와 재무 항목 지원은 구분한다.

## 코드 흐름

1. `frontend/src/main.jsx`의 `CompanyPicker`가 검색어·시장 필터로 `GET /api/companies`를 호출한다. 입력 후 250ms 대기하고 이전 요청을 취소한다.
2. `providers/registry.py`가 이름·종목코드·일부 한국어 별칭으로 공개 목록을 검색한다. 내부 식별자는 `DART:005930`, `SEC:AAPL`처럼 공급자를 포함한다.
3. `GET /api/company-data/{company_id}`는 등록된 ID만 수집 서비스에 전달한다.
4. `providers/service.py:load_financials()`가 성공 결과의 24시간 로컬 캐시를 확인하고 SEC/DART 어댑터를 선택한다. 회사별 잠금은 프로세스 내부에서만 적용한다.
5. 공급자 응답을 기간·통화·범위·출처가 붙은 공통 레코드로 정규화하고 `summary()`에서 Python 계산 함수를 호출한다.
6. `chat.py`가 기업·기간을 확인하고 단순 수치, 고정 RAG, Agent 경로를 선택한다. 라우팅 규칙과 이후 Agent의 도구 선택은 별개다.

## 수집 계약

| 항목 | SEC | OpenDART |
|---|---|---|
| 검색 목록 | SEC 목록의 공개 미러 스냅샷 | KRX 출처 스냅샷 |
| 기업 식별 | 선택한 티커를 SEC 제출 정보로 재확인 | 종목코드를 DART 고유번호로 변환하고 응답 확인 |
| 공시 선택 | 최근 보고 기간의 연간/수정공시 | 최근 완료된 2개 사업연도 중 조회 가능한 사업보고서 |
| 수치 범위 | 기업 전체 표준 XBRL 태그 | 연결(CFS), 별도(OFS)로 자동 대체하지 않음 |
| 기간 | 실제 시작·종료일과 연간 길이 검증 | 사업연도 라벨. 정확한 시작·종료일은 현재 레코드에 없음 |

목록의 출처는 [데이터 안내](../data/README.md)와 각 항목의 `directory_source`에 있다. 최신 종목·기업명과 모든 재무 항목을 보장하지 않는다. 기업 전용 태그, 금융업 등은 추가 매핑이 필요하다. 누락값을 0으로 채우거나 선택한 공시에 값이 없을 때 다른 공시로 조용히 대체하지 않는다.

원 단위 수치를 보존하고 화면에서 KRW는 억 원, 그 외 통화는 백만 단위로 표시한다. 회계연도와 달력 연도를 동일하게 가정하지 않는다. 구체적인 계산 정책은 [재무 데이터 해석](finance-reference.md)에 있다.

## 오류와 상태 관리

- 인증키가 들어간 공급자 요청 URL을 로그·응답에 노출하지 않는다.
- 공급자 실패는 정리된 오류로 반환한다. 다른 기업의 캐시나 고정 쿠팡 데이터로 대체하지 않는다.
- 기업 변경 시 진행 중인 브라우저 응답을 취소하고 이전 기업의 결과 반영을 막는다.
- 브라우저 취소 후 서버의 수집·캐시 작업은 계속될 수 있다.
- 다중 서버에서의 수집 중복 제어, 목록 갱신 자동화, 분기·기업 간 비교는 후속 과제다.

검증은 [test_companies.py](../tests/test_companies.py), [test_chat.py](../tests/test_chat.py)에서 기업 혼입·통화·기간·캐시·공급자 오류를 확인한다. 현재 API와 앱 흐름은 [아키텍처](architecture.md)를 참고한다.
