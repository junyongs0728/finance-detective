# 재무탐정 3분 시연

서버와 DB가 켜진 로컬 앱 `http://127.0.0.1:8000/` 기준이다. 외부 접속용 공개 데모는 아직 배포하지 않았다. 저장소는 비공개이며 링크만으로 채용 담당자가 볼 수 있는 상태는 아니다.

## 0:00–0:30 · 비용이 없는 수치 조회

쿠팡을 선택하고 `2025년 영업이익 알려줘`를 입력한다. 연간 수치·통화·기간·원문을 보여주고, LLM 없이 처리하는 이유를 설명한다.

> 단순 조회는 API 수치와 Python 계산으로 처리합니다. 모델이 필요한 설명·도구 선택에만 비용을 씁니다.

## 0:30–1:30 · 도구 선택과 검증된 계산

`2025년 영업현금흐름에서 영업이익을 뺀 차이를 계산하고 두 수치의 원본 근거 경로를 보여줘`

계산 카드, ‘분석 과정’, ‘기업과 근거의 관계 탐색’을 연다. 쿠팡 2025 공시에서 두 값의 차이 1,300,000,000 USD를 확인한 개발 사례다. 수치 선택 → 계산 → 출처 경로의 실제 실행 기록을 보여준다. 재실행 결과가 캐시이면 UI의 비용 0과 원래 실행 trace를 구분해 설명한다.

> LangGraph가 모델 선택과 도구 실행을 반복합니다. 계산 도구는 모델이 만든 숫자 대신 조회된 관측값 ID를 받고, 실제 기간·통화가 맞는지 검증합니다.

## 1:30–2:15 · 공시 기반 RAG

삼성전자를 검색·선택하고 `삼성전자의 반도체 사업을 공시 문단에 근거해 요약해줘`를 입력한다. 또는 애플의 `애플이 공시한 공급망 리스크를 설명해줘`를 사용한다. 첫 공시 준비는 다운로드·임베딩 시간과 비용이 별도로 필요하다.

번호가 붙은 인용, 원문 구간, 공시 링크를 열어 설명한다.

> 공시 범위를 먼저 고정하고 pgvector와 BM25 검색 순위를 합칩니다. 모델은 출처 구간 ID를 선택하고 원문 인용은 서버가 복사합니다. 별도 모델이 주장과 근거를 검토합니다.

## 2:15–3:00 · 실패와 한계

쿠팡으로 다시 변경하고 `쿠팡의 2025년 달 기지 운영 사업을 공시 근거로 설명해줘`를 입력한다. 근거 부족으로 답변을 보류하는지 보여준다. ‘공시 전체에 없다’는 단정과 ‘찾은 근거로 답할 수 없다’는 상태를 구분한다.

> 삼성전자 사례에서 회사 전체 투자액을 사업부 설명에 섞는 실패를 발견했습니다. 검토가 이를 차단했고, 생성 범위와 응답 스키마를 수정해 동일 개발 사례를 다시 검증했습니다.

평가 보고서의 작은 개발 집합을 일반 정확도라고 설명하지 않는다. 공개 배포·부하 시험·작업 큐·더 넓은 문서/질문 평가가 남았음을 명시한다.
